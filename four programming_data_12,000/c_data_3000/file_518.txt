using System;
using System.Net.Sockets;
using System.Threading.Tasks;

class Program
{
    static void Main(string[] args)
    {
        var path = "/tmp/foo.sock";

        // client
        Task.Run(async () =>
        {
            // wait 2 seconds
            await Task.Delay(2000);

            using (var socket = new Socket(AddressFamily.Unix, SocketType.Stream, ProtocolType.Unspecified))
            {
                socket.Connect(new UnixDomainSocketEndPoint(path));

                // send hello world
                var dataToSend = System.Text.Encoding.UTF8.GetBytes("Hello-world!");

                socket.Send(dataToSend);
            }
        });

        // Server
        {
            // delete file if it exists
            if (System.IO.File.Exists(path))
                System.IO.File.Delete(path);

            var socket = new Socket(AddressFamily.Unix, SocketType.Stream, ProtocolType.Unspecified);
            socket.Bind(new UnixDomainSocketEndPoint(path));
            socket.Listen(5);
            Console.WriteLine("Server started waiting for client to connect...");

            var s = socket.Accept();

            Console.WriteLine("Client connected");

            var buffer = new byte[1024];
            var numberOfBytesReceived = s.Receive(buffer, 0, buffer.Length, SocketFlags.None);

            var message = System.Text.Encoding.UTF8.GetString(buffer, 0, numberOfBytesReceived);

            Console.WriteLine($"Received: {message}");
        }

    }

Although it is possible to free things all at once, it's better to use a few subfunctions to do the job. Just like Make* functions, we could create Free* functions.
A good maxim might be: If a function [or statement] "seems" overly complex or error prone, it might need to be split up into smaller functions.
In fact, in the example below, I cannibalized the Make* functions to create the Free* functions.
In the original Make* functions, the function was passed a pointer to the struct it was creating/initializing. If that pointer was NULL, it was doing a malloc. Thus, it "knows" whether it's doing the malloc or not.
That allowed the function to either create a "free standing" struct with malloc [as MakeCache did] or have the struct be a subordinate of another struct (e.g. Set was subordinate to Cache and Line was subordinate to Set). This may not be the most optimal way to do it [a seperate "alloc" and "init" function might be cleaner].
However, for a Free* function, the caller would have to "tell" the function whether to do a free of the struct pointer or not. This would be messy as the caller would have to keep track of [such] things. Usually, keeping track of that is the province of the individual functions.
So, I've added an extra member to each struct that "remembers" whether the struct was allocated or not. Then, the Free* function can look at that to determine whether it can free its pointer or not. This is a personal "trick of the trade" that I've used a lot in production code. This field could just be an boolean int (as in cache_alloced). But, I chose to use a bit mask with various option bits (e.g. OPT_ALLOC). This is to allow for future expansion if needed.
I've created a few helper CPP macros to assist in this [be careful what you wish for, you might actually get it :-)].
You may notice that the various FREEME* macros first check if the "about to be freed" pointer is NULL, and suppress the call to free if so. This isn't really necessary because it is permissible to call free with a null pointer [i.e. it is harmless].
Another thing they do is, after the free, they set the pointer to NULL. This is a "safety" feature to catch misuse/reuse of a "freed" pointer. It also prevents a "double free" abort from free (e.g. free(ptr); free(ptr); would cause this).
If the pointer is not nulled, the dereference might succeed with undefined results. That is UB [undefined behavior] but might be hard to detect. By zeroing out the pointer, any subsequent dereference of the pointer would trigger an immediate SIGSEGV [segfault].
Side note: I followed your convention for naming functions. And, although I didn't do it herein, I've found it useful to reverse the "object" and "verb". That is, instead of (e.g.) MakeCache and FreeCache, I'd do: CacheMake and CacheFree. That way, if there were more functions that operated on a given struct pointer, they would "line up" if we produced a sorted list of all functions.

    t--;

    }

A pointer is a variable which contains the address of something. Using a pointer you can look at and/or change the thing it points to. If you increment the pointer, you're changing the address in the pointer, and thus you're changing what it points to.
In this code all of the pointer arithmetic is done in the for loop for( ; *code ; ++code) in the analyse function. What we're saying here is that A) there's no initialization section (there's no code before the first ; in the for statement); B) we want to continue as long as what's being pointed at the the code pointer is not zero *code in the "test" portion of the for statement; and C) after each pass through the loop we want to increment the code pointer (++code in the "increment" section of the for statement).
If you wanted to you could replace the for loop in analyse with:
while(*code <> 0)
  {
  if (*code == '.')
    *p_dots += 1;

  if (*code == '-')
    *p_dashes += 1;

  code += 1;
  }
