Why do arrays in C decay to pointers?

                                (3 answers)
                            

Closed 1 year ago.



I stumbled into a weirdness today with the C language that I cannot understand the reasoning behind. 
If i have a function like this (assume 32 bit architecture):
void printSize(char array[6]) {
    printf("%zd\n", sizeof array);
}

I will get back 4, which is the size of the pointer. I was expecting to get 6, which is the explicitly declared size in the function prototype.
I get that arrays are passed by reference, and that the underlying type is a pointer. I was assuming that putting the length of the array in the prototype would provide the compiler with the information it needed to return 6.
why does C do this? Also, what is the point of putting a size in a prototype if the compiler can't even do sizeof(), returning that size?The behavior you've observed is mandated by the C standard.  Section 6.7.6.3p7 regarding "Function declarators" states:

A declaration of a parameter as ‘‘array of type’’ shall be adjusted to
  ‘‘qualified pointer to type’’, where the type qualifiers (if any) are
  those specified within the [ and ] of the array type derivation. If
  the keyword static also appears within the [ and ] of the array type
  derivation, then for each call to the function, the value of the
  corresponding actual argument shall provide access to the first
  element of an array with at least as many elements as specified by the
  size expression.

So the reason compilers do this is because the standard says they must.  Also, from a pragmatic standpoint, it would mean you couldn't pass an actual pointer to such a function.  Consider if an array was passed to a function whose parameter type was int * and then passed to a function whose paameter type was int [5], or an array that was allocated dynamically i.e. int *arr = malloc(5 * sizeof(int));
Also, note that this only applies to the first dimension of a multidimensional array.  That means that this:
void foo(int arr[4][5])

is the same as
void foo(int (*arr)[5])

But not:
void foo(int **arr)Arrays are not "passed by reference". Nothing in C is "passed by reference". Everything is passed by value. 
Arrays, when "passed" to functions as arguments, decay to a pointer to the first element of the array.

The thing is sysfs_notify_dirent() requires the kernfs_node that corresponds to the sysfs attribute you want to notify changes of. While with sysfs_notify() you need to pass the device kobj, the subdirectory name (or NULL if there is no subdirectory) and the attribute name. The question is: how do you find the kernfs_node of the attribute?
The struct kobject has a member struct kernfs_node *sd which is a pointer to the kernfs_node that corresponds to the kobj directory path.
So from your device kobject you already have the kernfs_node of your sysfs device's root directory. With it you need to obtain your attribute's kernfs_node using the function sysfs_get_dirent() to which you need to pass the kernfs_node and the name of the attribute or subdirectory you want the kernfs_node of.
Let's see a small example. Say your device kobject pointer is mykobj and it's name is "mydevice" and you have a subdirectory called "mysubdir" and an attribute "myattr". This is how you get the kernfs_node of the subdirectory and the attribute:
/* This is our main kernfs_node */
struct kernfs_node *mydevice_kn = mykobj->sd;
/* This is our subdirectory kernfs_node */
/* We get the mydevice_kn child node thats named "mysubdir" */
struct kernfs_node *mysubdir_kn = sysfs_get_dirent(mydevice_kn, "mysubdir");
/* This is our attribute kernfs_node */
/* We get the mysubdir_kn child node thats named "myattr" */
struct kernfs_node *myattr_kn = sysfs_get_dirent(mysubdir_kn, "myattr");

Once you have the kernfs_node of your desired attribute, you can pass it to your sysfs_notify_dirent() function. From a computer perspective, you could think of flow as being in a state where your instruction and data caches have all of the code and information needed to do a complex computation.
