For scanf, both of the %c and %s conversion specifiers expect their corresponding argument to have type "pointer to char" (char *); however, what that pointer means and how scanf behaves is different between the two.
In the case of %c, you pass a pointer to a single char object, and the next character read from the input stream (whitespace or not) will be stored to it.  If you want scanf to skip over leading whitespace and read the next non-whitespace character, put a blank space before the %c conversion specifier in the format string, like so:
scanf( " %c", &class ); // read the next non-whitespace character into class

To obtain the pointer to your target object, use the & operator as shown above.
In the case of %s, you pass a pointer to the first element of an array of char; scanf will skip over any leading whitespace, then read and store a sequence of non-whitespace characters to that array, stopping when it sees a whitespace character.  If your input contains the sequence
'\n', ' ', 'T', 'h', 'i', 's', ' ', 'i', 's', ' ', 'a', ' ', 't', 'e', 's', 't', '\n'

The %s specifier tells scanf to read and discard the leading '\n' and ' ', then read the string "This" into your array, leaving the following in the input stream:
' ', 'i', 's', ' ', 'a', ' ', 't', 'e', 's', 't', '\n'

Here's where things get confusing, though - when you pass an array expression as the argument, you don't use the & operator:
char string[21]; // large enough for a 20-character string
...
scanf( "%s", string );

The expression string in the scanf call is converted ("decays") from type "21-element array of char" to "pointer to char", and its value is the address of the first element of the array.  It's exactly equivalent to writing
scanf( "%s", &string[0] );

Having said all that...
scanf is an awful tool for reading interactive input.  It's convenient if you can guarantee your input will always be well-formed, but otherwise it's a lot of work to detect and handle badly formed input. Why happens that?Before you call pthread_cond_wait, you have to check that the thing you are waiting for hasn't already happened. And before you call pthread_cond_signal (or before you release the mutex if you call it while holding the mutex) you have to change the shared state protected by that mutex so that other thread will know that the thing they are waiting for has happened.
You are using a condition variable as if it was a semaphore. It's not. Condition variables are stateless and it's up to your code to track the state with the associated mutex. Your code doesn't do that.
You code has some shared state -- which thread is supposed to be running and which thread is supposed to be waiting. To use a condition variable to wait for that state to change, that state must be protected with the associated mutex. But you don't even track that state at all! Lets look at 4 iterations on the example 13, 1101 in binary.
1101 ^ 0001 is 1100
1100 ^ 0010 is 1110
1110 ^ 0100 is 1010
1010 ^ 1000 is 0010

0010 is 1101 ^ 1111

Why not, instead, try matrix traversal? i.e construct an imaginary matrix, taking the current pixel ([i][j]) as center, now traverse all the valid pixels of said matrix and add them up. Simple and efficient.
// Blur image
void blur(int height, int width, RGBTRIPLE image[height][width])
{

    RGBTRIPLE old[height][width];
    for (int i = 0; i < height; i++)
    {
        // Copy the original image over to a temporary variable, row by row
        memcpy(old[i], image[i], sizeof(RGBTRIPLE) * width);
    }
    // Iterate through rows
    for (int i = 0; i < height; i++)
    {
        // Iterate through columns
        for (int j = 0, red, green, blue, count; j < width; j++)
        {
            // Reset the variables
            red = blue = green = count = 0;
            // Move row-wise in the imaginary matrix (centered around [i][j])
            for (int r = i - 1; r <= i + 1; r++)
            {
                // Move column-wise in the imaginary matrix (centered around [i][j])
                for (int c = j - 1; c <= j + 1; c++)
                {
                    // Check for invalid pixels
                    if (r < 0 || r > height - 1)
                    {
                        // Invalid row, no need to continue, move on to next row
                        break;
                    }
                    if (c > -1 && c < width)
                    {
                        // Valid pixel
                        count++;
                        // Sum up every pixel color
                        red += old[r][c].rgbtRed;
                        green += old[r][c].rgbtGreen;
                        blue += old[r][c].rgbtBlue;
                    }
                }
            }
            // Calculate the average and assign
            image[i][j].rgbtRed = round((float)red / count);
            image[i][j].rgbtGreen = round((float)green / count);
            image[i][j].rgbtBlue = round((float)blue / count);
        }
    }
    return;
}

On gcc above 7 you could use a attribute:
__attribute__((__fallthrough__));

On gcc above 10 you could use the attribute from C2x:
[[fallthrough]];

Trap in situations where the compiler can recognize that an out-of-bounds access is occurring.
