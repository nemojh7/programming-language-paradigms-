The idea is OUT[body1] is going to use multiple elements from the same cache block for several consecutive values of body1. However, those uses of consecutive values of body1 do not occur one after the other. They are spread out because the entire loop on body2 is executed between them. Presumably, using compute(body1, body2) causes use of various memory depending on body2 values.
The notion is that, over the course of the body2 loop, so many different places in memory will be accessed that the cache block associated with OUT[body1] will be evicted from cache, so, when body1 is incremented to the next value, but OUT[body1] would still be in the same cache block, that block is no longer in cache and has to be loaded again.
