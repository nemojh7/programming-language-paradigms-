double simple_strtod(const char* str)
{
 int8 inc;
 double result = 0.0;
 char * c_tmp;
 c_tmp = strchr(str, '.');
 if(c_tmp != NULL)
 {
    c_tmp++;
    inc = -1;
    while(*c_tmp != 0 && inc > -9)
    {
        result += (*c_tmp - '0') * pow(10.0, inc);
        c_tmp++; inc--;
    }
    inc = 0;
    c_tmp = strchr(str, '.');
    c_tmp--;
    do
    {
        result += (*c_tmp - '0') * pow(10.0,inc);
        c_tmp--; inc++;
    }while(c_tmp >= str);
 }
 return result; 
}

// get current terminal and check whether it's in our list of terminals
// supporting ANSI colors:
static int isAnsiColorTerm(void)
{
    char *term = getenv("TERM");
    for (const char **ansiTerm = &ansiColorTerms[0]; *ansiTerm; ++ansiTerm)
    {
        int match = 1;
        const char *t = term;
        const char *a = *ansiTerm;
        while (*a && *t)
        {
            if (*a++ != *t++)
            {
                match = 0;
                break;
            }
        }
        if (match) return 1;
    }
    return 0;
}

void setTextColor(FILE *stream, TextColor color)
{
    int outfd = fileno(stream);
    if (isatty(outfd) && isAnsiColorTerm())
    {
        // we're directly outputting to a terminal supporting ANSI colors,
        // so send the appropriate sequence:
        fputs(ansiColorSequences[color], stream);
    }
}

Edit: To clear up, I'm asking for the k-th smallest key in the B-tree.There's no efficient way to do it using a standard B-tree. Broadly speaking, I see 2 options:

Convert the B-tree to an order statistic tree to allow for this operation in O(log n).
That is, for each node, keep a variable representing the size (number of elements) of the subtree rooted at that node (that node, all its children, all its children's children, etc.).
Whenever you do an insertion or deletion, you update this variable appropriately. You will only need to update nodes already being visited, so it won't change the complexity of those operations.
Getting the k-th element would involve adding up the sizes of the children until we get to k, picking the appropriate child to visit and decreasing k appropriately. Pseudo-code:
select(root, k) // initial call for root

// returns the k'th element of the elements in node
function select(node, k)
   for i = 0 to t.elementCount
      size = 0
      if node.child[i] != null
         size = node.sizeOfChild[i]
      if k < size // element is in the child subtree
         return select(node.child[i], k)
      else if k == size // element is here
               && i != t.elementCount // only equal when k == elements in tree, i.e. k is not valid
         return t.element[i]
      else // k > size, element is to the right
         k -= size + 1 // child[i] subtree + t.element[i]
   return null // k > elements in tree

Consider child[i] to be directly to the left of element[i].
The pseudo-code for the binary search tree (not B-tree) provided on Wikipedia may explain the basic concept here better than the above.
Note that the size of a node's subtree should be store in its parent (note that I didn't use node.child[i].size above). Storing it in the node itself will be much less efficient, as reading nodes is considered a non-trivial or expensive operation for B-tree use cases (nodes must often be read from disk), thus you want to minimise the number of nodes read, even if that would make each node slightly bigger.
Do an in-order traversal until you've seen k elements - this will take O(n).

}The rod cut problem basically states that given a rod that we can cut into discrete increments, and prices for those discrete sizes of rod, how do we cut the rod such that we get the best price for it as a whole. In your example, you pass your function an array of size 3 {17, 17, 1} which, given our problem statement, says that a piece of rod of size 1 is work 17 units, a piece of size 2 is worth 17 units, and piece of size 3 is worth 1 unit. Obviously, the optimal solution to your example would be to cut the rod into single units and sell it. The example in the link you provided has a price list like this: {1,5,8,9,10,17,17,20}. The solution for this is less obvious and requires a more nuanced approach to solve it. This type of situation is one where the recursive solution shows it's value. 
Your solution seems to attempt to solve the naive recursive version of this problem, where we do not consider things like overlapping sub-problems discussed in the link you provided. To solve this the naive way, you examine all of the sub-problems and return their max results, then combine them to find the global maximum. For instance, for a rod of size 8, you need to find the maximum prices returned for a rod of size 7, 6, 5... and combine those options to find a global maximum. Your solution doesn't find and combine those options, which is why you are not getting hte correct result. The most intuitive way to examine and combine all sub-problems for this problem is to do something like this pseudocode:
def cutRod(arr price[], int n)
   if(n <= 0)
     return 0;
   int max_val = -inf //set maximum value to negative infinity
   for(int i = 0; i<n; ++i)
     max_val = max(max_val, price[i] + cutRod(price, n-i-1));
   return max_val;

This is basically the code given as the naive example in your link provided. What it does is loop over all of the possible price options for a given size of rod an sum the value returned by selling said size of rod for its given price, and the maximum price possible for the rest of the rod. For their example {1,5,8,9,10,17,17,20}, the code would first find the max price for a rod cut at position 1, so you add price[0] with cutRod(price, 7). This finds the maximum price you can sell a rod of size 7 for, which is 18 (17 and 1), and adds price[0] to that, returning 19. This process continues, until you find the maximum value for all of the subproblems, which ends up being 22.  
As you can see, in this example we examine basically every possible reasonable option for our rod cut scenario, where as in your code above, you examine only some options, many of which don't actually sell the entire rod.

    If new data received:
        Increment received_len by the received amount
        Increment have_received by 1
        If a separator exists in received[0..received_len-1]:

            Copy the first N chars of received[] to the new structure
            Lock the incoming_lock mutex

            Unlock the incoming_lock mutex

                received_len -= N

            End If
        End If
    End If

    Unlock received_lock mutex
