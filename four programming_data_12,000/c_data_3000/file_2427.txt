Footnote: Why you should never use sprintf.
It's suggested that it's OK to use sprintf so long as you know the input 
sizes. 
It's still a risk and well written programs don't use it anymore.
It always risks some change in some other part of the program that changes output sizes. That's a classic downstream calamity. Change in an int to a long (or from 32 to 64 bit...) and Boom. 
It's deprecated by the standard not just for user input but all input for good reason. Or maybe you just got a sum wrong and the program fails in obscure circumstances when a number of variables are near their limit.
Suppose a log message prints out a user name a date and a size and a sleeping bug that the buffer is just too short. Depending on your date format you might have a bug that only crashes for certain users at certain times of the month!
Don't use sprintf(). There's really no point worrying about. The result buffer must be large enough to contain the characters written by sprintf(). If there is uncertainty about sizes involved, it is safer to use snprintf() (since C99). The return value of this function is negative if there was an error in the function call, otherwise it is the number of characters that would have been written to an appropriately sized buffer, less the null terminator. This return value could be used to check to see if output was truncated, or could be used to allocate a buffer of the correct size.
The latter approach is illustrated in the below code. First, snprintf() is called to write zero characters to a null pointer target. The return value, n, is the number of characters that would have been written to an appropriately sized buffer. This value could be used to declare a VLA, but this array could not be resized later if needed again; here malloc() is used to allocate space, including space for the null terminator. If the result buffer is needed again, it can be reallocated to a new size. This memory must be deallocated before exiting the program.
Note that the return value of snprintf() is checked for errors. The return value of malloc() is also checked for errors.
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    size_t sz = 100;
    char *length = "LEN";
    int n;

    n = snprintf(NULL, 0,"%zu%s", sz, length);
    if (n < 0) {
        fprintf(stderr, "Error in snprintf() size evaluation\n");
        exit(EXIT_FAILURE);
    }

    /* Could use a VLA, but this cannot be resized */
//    char result[n+1];

    /* Using malloc() allows result to be reallocated later if necessary */
    size_t result_sz = n + 1;
    char *result = malloc(result_sz);
    if (result == NULL) {
        fprintf(stderr, "Allocation error\n");
        exit(EXIT_FAILURE);
    }

    n = snprintf(result, result_sz, "%zu%s", sz, length);
    if (n < 0) {
        fprintf(stderr, "Error in snprintf() write\n");
        exit(EXIT_FAILURE);
    }

    printf("%s\n", result);

    free(result);

    return 0;
}

Thank you for taking the time to read my question and helping me understand the memory layout.Pointer Refresher
A pointer is just a numeric value that holds the address of a value of type T. This means that T can also be a pointer type, thus creating pointers-to-pointers, pointers-to-pointers-to-pointers, and crazy things like char********** - which is simply a pointer (T*) where T is a pointer to something else (T = E*) where E is a pointer to something else (and so on...).
Something to remember here is that a pointer itself is a value and thus takes space. More specifically, it's (usually) the size of the addressable space the CPU supports.
So for example, the 6502 processor (commonly found in old gaming consoles like the NES and Atari, as well as the Apple II, etc.) could only address 16 bits of memory, and thus its "pointers" were 16-bits in size.
So regardless of the underlying type, a pointer will (usually) be as large as the addressable space.
Keep in mind that a pointer doesn't guarantee that it points to valid memory - it's simply a numeric value that happens to specify a location in memory.
Array Refresher
An array is simply a series of T elements in contiguously addressable memory. The fact it's a "double pointer" (or pointer-to-a-pointer) is innocuous - it is still a regular pointer.
For example, allocating an array of 3 T's will result in a memory block that is 3 * sizeof(T) bytes long.
When you malloc(...) that memory, the pointer returned simply points to the first element.
T *array = malloc(3 * sizeof(T));
printf("%d\n", (&array[0] == &(*array))); // 1 (true)

Keep in mind that the subscript operator (the [...]) is basically just syntactic sugar for:
(*(array + sizeof(*array) * n)) // array[n]

Arrays of Pointers
To sum all of this up, when you do
E **array = malloc(3 * sizeof(E*));

You're doing the same thing as
T *array = malloc(3 * sizeof(T));

where T is really E*.
Two things to remember about malloc(...):

It doesn't initialize the memory with any specific values (use calloc for that)
It's not guaranteed (nor really even common) for the memory to be contiguous or adjacent to the memory returned by a previous call to malloc

Therefore, when you fill the previously created array-of-pointers with subsequent calls to malloc(), they might be in arbitrarily random places in memory.
All you're doing with your first malloc() call is simply creating the block of memory required to store n pointers. That's it.

#include <stdio.h>
#include <stdlib.h>

void dice_sum_probabilities(int n, int d) {
    // Compute the polynomial [(x+x^2+...+x^d)/d]^n.
    // The coefficient of x^k in the result is the
    // probability of n dice with d sides summing to k.
    int N=d*n+1;
    // p is the coefficients of a degree N-1 polynomial.
    double p[N];
    for (int i=0; i<N; i++) p[i]=i==0;
    // After k iterations of the main loop, p represents
    // the polynomial [(x+x^2+...+x^d)/d]^k
    for (int i=0; i<n; i++) {
        // S is the rolling sum of the last d coefficients.
        double S = 0;
        // This loop iterates backwards through the array
        // setting p[j+d] to (p[j]+p[j+1]+...+p[j+d-1])/d.
        // To get the ends right, j ranges over a slightly
        // larger range than the array, and care is taken to
        // not write out-of-bounds, and to treat out-of-bounds
        // reads as 0.
        for (int j=N-1;j>=-d;j--) {
            if (j>=0) S += p[j];
            if (j+d < N) {
                S -= p[j+d];
                p[j+d] = S/d;
            }
        }
    }
    for (int i=n; i<N; i++) {
        printf("% 4d: %.08lf\n", i, p[i]);
    }
}
