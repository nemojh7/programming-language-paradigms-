Yes, a struct is a value, so assigning an address to a variable and a value to that address works the same way. The difference is that a struct might take more memory than an int depending on its members. This affects what address is available for the next variable.
Note that the addresses assigned will be offsets from some base memory address. When the OS loads the executable, it gives this base address and the executable calculates the absolute memory addresses by adding the offsets to the base address.

C11, 6.10.3 Macro replacement states:

An identifier currently defined as an object-like macro shall not be redefined by another #define preprocessing directive unless the second definition is an object-like macro definition and the two replacement lists are identical. [..]

As noted, it's not a constraint violation if the replacement is identical. So
#define X 1
#define X 2

requires a diagnostic; whereas
#define X 1
#define X 1

is OK. Similar constraints apply for function-like macros (C11, 6.10.3, 2).This:
#define Dummy 1
#define Dummy 2

is the same as:
#define Dummy 2

But you'll get probably (I'm not sure what the standard says) a warning such as 'Dummy': macro redefinition for the second #define
In other words: the last #define wins.
If you want to do things properly, you should use #undef:
#define Dummy 1
#undef Dummy
#define Dummy 2    // no warning this time

BTW: there are scenarios where it is perfectly OK to change the definition of a macro.An example from C Standards#6.10.3.5p8

EXAMPLE 6 To demonstrate the redefinition rules, the following sequence is valid.
      #define      OBJ_LIKE      (1-1)
      #define      OBJ_LIKE      /* white space */ (1-1) /* other */
      #define      FUNC_LIKE(a)   ( a )
      #define      FUNC_LIKE( a )( /* note the white space */ \
                                   a /* other stuff on this line
                                       */ )

      #define      OBJ_LIKE    (0)     // different token sequence
      #define      OBJ_LIKE    (1 - 1) // different white space
      #define      FUNC_LIKE(b) ( a ) // different parameter usage
      #define      FUNC_LIKE(b) ( b ) // different parameter spelling

Why is it?
Much will depend on how the values are written to your inputfile. (are they written as int -- e.g. 4-bytes per value, or unsigned char, 1-byte per value?)
int and unsigned char are not interchangeable. You can read data in whatever sized chunks you like, using either int or unsigned char, but you can't have written data as unsigned char values, and expect to read the values back in as int -- you can't (unless you manually account for the type-size difference and OR and/or shift the needed bytes from each int). 
In one case values were written in 1-byte representations, in the other, values were written in 4-byte representation. So you must properly size (or otherwise account for) the type of values originally written to the file.
Why is it? -- is a failure to match your read of the number of bytes as they were written. The type you choose for buffer effects pointer arithmetic and will result in differences in what is contained in buffer[0], buffer[1], etc.. For example if you declare
char *buffer;      /* or just buffer[512] */

Then each index is buffer represents 1-byte of information. So if your file contains
ffd8ffea           /* 0xff 0xd8 0xff 0xea */

Reading with buffer will result in buffer[0] = 0xff, buffer[1] = 0xd8, etc.... However, if you declare:
int *buffer;      /* or just buffer[512] */

Reading with buffer will result in buffer[0] = 0xffd8ffea, buffer[1] = (next 4-bytes), etc... So depending on what is in your inputfile, your problem is here:

ff000000d8000000ff000000ea000000   /* each value represented by 4-bytes */

If you wanted to send a signal to your C program whenever the file changes, you would go to the line with *** MARKER *** and insert a call to kill. Then set up a signal handler in your C program that handles SIGHUP for example. Signal handler setup is described here. Here is a quick example:
#include <unistd.h>
#include <chrono>
#include <thread>
#include <csignal>
#include <iostream>

int nSignals;

void signal_handler(int signal)
{
   std::signal(SIGHUP, signal_handler);
   std::cout << "Got signal" << std::endl;
   nSignals++;
}

int main()
{
   // Install a signal handler
   std::signal(SIGHUP, signal_handler);

   std::cout << "Send me a signal with: kill -HUP " << (int)getpid() << std::endl;

   while(nSignals<5){
      std::cout << "Received " << nSignals << " of 5 signals, sleeping..." << std::endl;
      std::this_thread::sleep_for(std::chrono::seconds(5));
   }
}
