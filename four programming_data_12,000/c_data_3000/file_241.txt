The proper return type depends on the functions whose addresses you want to return, and on what you want the caller to be able to do with them.  If you only cared about returning the addresses, not doing anything with them, then any function pointer type will do, but you will have to cast.  For example,
typedef void (*func_ptr)(void);

func_ptr get_func_pointer(void) {
    return (func_ptr) str_func;
}

But using some random function type does not provide for calling the function.  The pointer must be cast back to a function pointer type compatible with the pointed-to function before it can be used to call that function, and the caller somehow needs to know what that is in order to do so:
    typedef char * (*str_func_ptr)(const char* n);

    str_func_ptr p = (str_func_ptr) get_func_pointer();
    p("argument");

Under most circumstances, it is better to have the function return a function pointer of the correct type in the first place. Of course, such a function is suitable only for returning pointers to functions having the chosen signature.
Also, I reiterate my comment that formally, function pointers are not compatible with any object pointer type, including void *.  The language specification does not provide for converting function pointers to type void *, and although it does permit converting them to integer types such as intptr_t, it does not provide a sound basis for relying on any such conversions to be lossless.

A pointer to func1 would have type void (*)(int, int) - "pointer to function taking two int parameters and returning void".  You would declare a pointer variable of this type as
void (*p)(int, int) = func1;

If you want to declare a function returning that type, you’d just replace p with the function prototype:
void (*   p     )(int, int);
          |
       +––+––––+
       |       |
       v       v
void (*foo(void))(int, int);

void (*foo(void))(int, int)
{
  return func1;
}

The declaration reads as
       foo                   –– foo is
       foo(    )             –– a function taking
       foo(void)             ––   no parameters
      *foo(void)             –– returning a pointer to
     (*foo(void))(        )  ––   a function taking
     (*foo(void))(        )  ––     unnamed parameter is
     (*foo(void))(int     )  ––     int
     (*foo(void))(int,    )  ––     unnamed parameter is
     (*foo(void))(int, int)  ––     int
void (*foo(void))(int, int)  ––   returning void

You could create a typedef for func1's type (we’ll call it func1_t) and return a pointer to that:
typedef void func1_t(int, int);

func1_t *foo( void )
{
  return func1;
}

I would strongly discourage hiding pointers behind typedefs - IME they create maintenance problems.

This statement:

*x = *x + 1;

says to get the value of *x, add one to it, and store the result in *x.

If *x has an atomic type, then this statement has two separate accesses to *x, one to read it and one to write it. It is possible for other operations on *x to occur between this read and this write. Contrast this with *x += 1; below.
(Volatile and atomic types are rare in most programs. Although they are important and indeed are in frequent use, their uses are often restricted to special parts of programs and operating systems, so normal code does not have to deal with them.)

Or modulo wrapping is what happens when an unsigned integer overflows.
When working with a fixed number of digits/bits, arithmetic operations can overflow the fixed number of digits.  But the overflow portion cannot be represented in the fixed number of digits/bits and is basically masked away.  The overflow portion can be considered a modulus and the portion within the fixed number of digits/bits is the remainder or modulo.  Given the modulus, the modulo value remains correct/congruent after the operation that caused the overflow.
The best way to understand is to do a few operations with a pen on paper.  Choose a base.  Hexadecimal is great but it works for decimal, binary, and every base.  Choose a fixed number of digits/bits.  For uint32_t you have 8 hex digits or 32 bits.  Choose two values that will overflow the fixed number of digits when you add them.  Do the math on paper and include any overflow into an extra digit.  Now perform the modulo operation by covering the overflow with your hand.  Your CPU does this modulo operation automatically by virtue of having a fixed number of digits (i.e., uint32_t).  Repeat this with different numbers and repeat with a subtraction/underflow.  Eventually you'll start to trust that it works.
You do have to be careful when setting up this operation.  Use unsigned types and subtract the start ticks value from the current ticks value, like is done in your example code.  (Do not, for example, add the delay to start ticks and compare with the current ticks.)  Raymond Chen's article, Using modular arithmetic to avoid timing overflow problems has more information.

{
    pid_t pid;

    pid = fork();
    if (pid == 0)
    {
        // Child process
        if (execvp(args[0], args) == -1)
        {
            perror("ash");
        }
        exit(EXIT_FAILURE);
    }
    else if (pid < 0)
    {
        // Error forking
        perror("ash");
    }
    else
    {
        // Parent process
        do
        {
            waitpid(pid, &status, WUNTRACED);
        } while (!WIFEXITED(status) && !WIFSIGNALED(status));
    }

    return 1;
}

char **ash_split_line(char *line)
{
    int bufsize = ASH_TOK_BUFSIZE, position = 0;
    char **tokens = (char **)malloc(bufsize * sizeof(char *));
    char *token, **tokens_backup;

    if (!tokens)

        exit(EXIT_FAILURE);
    }

    token = strtok(line, ASH_TOK_DELIM);
    while (token != NULL)
    {
        tokens[position] = token;
        position++;

        if (position >= bufsize)
        {
            bufsize += ASH_TOK_BUFSIZE;
            tokens_backup = tokens;
            tokens = (char **)realloc(tokens, bufsize * sizeof(char *));
            if (!tokens)

                exit(EXIT_FAILURE);

        token = strtok(NULL, ASH_TOK_DELIM);
    }
    tokens[position] = NULL;
    return tokens;
}
