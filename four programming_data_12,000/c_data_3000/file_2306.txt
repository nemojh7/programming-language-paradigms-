Absolutely!  But it requires a fair amount of preprocessor metaprogramming.  Methinks you might be facing yet another tradeoff.
Nevertheless, here it is; this is one approach showing you what it takes to pull this off.
Caveat
One thing that we cannot do is use macros to evaluate expressions; and by expression I'm referring to grammatical entities defined by the language using the typical symbolic operators.
For example, given X, Y, and Z are defined as integer literals (with reasonable range), we can with some difficulty come up with a macro set such that SUM(X,Y,Z) expands to the sum; but it's impossible to come up with a macro set such that COMPUTE(X+Y+Z) expands to the sum.
In particular, you showed an example usage:
/* Won't work: */ DECLARE_READ(long long, /* --> */ NEOF|NSGN, readll)

No matter how we define DECLARE_READ, there's not much useful to be done with NEOF|NSGN.  A more natural version of a feature set for CPP programming would simply be a tuple of tokens; that would look more like this:
DECLARE_READ(long long, (NEOF,NSGN), readll)

...now that we can code to!
Interface macros
Before getting into the implementation of this approach, I'll start with the "interface"; that is, the macros you'll actually be dealing with.  First, there are some high level formal concepts to nail down.
Let's say that a feature is a particular token you'll use in a feature set.  For each feature, you need to define a matching pattern macro for the framework:
#define NEOF_test_NEOF ,Y
#define NSGN_test_NSGN ,Y
#define LAZY_test_LAZY ,Y

These pattern macros are used by a core pattern matcher to in effect implement an equality comparison operator for features.  This serves an analogous need to the use of bitwise operations, where you would need to allocate unique bits within an integer to each feature (#define NEOF 1, #define NSGN 2, #define LAZY 4, and so on).
Given a set of features, a feature set is a tuple of features; that is, a feature set is defined by a comma delimited set of features surrounded by parentheses, as mentioned at the top of the post, like this:  (NEOF,NSGN).
This in mind, the framework supports a macro:
HAS_FEATURE(Q_,FSET_)

...where Q_ is a feature, and FSET_ is a feature set, this macro expands to Y if the specified feature is in the feature set; otherwise it expands to N.  For example, given the above features:
HAS_FEATURE(LAZY,(NEOF,NSGN)) // expands to N
HAS_FEATURE(NSGN,(NEOF,NSGN)) // expands to Y

This macro:
EXPAND_IF(PREDICATE_,TO_)

...accepts Y or N as the first argument.  The second argument is a series of tokens within parentheses.  If called with Y as the first argument, this will expand to the specified set of tokens with the parentheses removed.  If called with N as the first argument, this expands to nothing.
This is enough interface to literally implement your sample macro:

        size_t number_of_elemens, \
        size_t element_size \

                (, void* rvmnyc) \
        ) /* #endif */ \

        /* ctor logic here */ \
    }

LOGICAL_NOT(C_)
LOGICAL_OR(...)
LOGICAL_AND(...)

All of these accept only Y and N as arguments; the LOGICAL_OR and LOGICAL_AND operators can be used with multiple arguments (up to 9 but can be expanded).

int writeListToFile(const link_t *list) {

        for (; list != NULL; list = list->next) {
            fprintf("  { "\"name\": \"%s\", \"duration\": %u, \"path\": \"%s\" },\n",
                    list->frame->name, list->frame->duration, list->frame->path);

        fclose(pfile);

Reading file contents faster than fgets() is feasible, but seems beyond your skill level. Learn the simple stuff first.  There is an awful lot that can be achieved with standard line by line readers... Very few use cases warrant the use of more advanced approaches.
If you want to read the whole input and parse it as a single string, here is a generic solution that should work for all (finite) input types:
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    size_t pos = 0, size = 1025, nread;
    char *buf0 = malloc(size);
    char *buf = buf0;

    for (;;) {
        if (buf == NULL) {
            fprintf(stderr, "not enough memory for %zu bytes\n", size);
            free(buf0);
            exit(1);
        }
        nread = fread(buf + pos, 1, size - pos - 1, stdin);
        if (nread == 0)
            break;

        pos += nread;
        /* Grow the buffer size exponentially (Fibonacci ratio) */
        if (size - pos < size / 2)
            size += size / 2 + size / 8;
        buf = realloc(buf0 = buf, size);
    }
    buf[pos] = '\0';

    // parse pos bytes of data in buf as a string
    printf("read %zu bytes\n", strlen(buf));        

    free(buf);
    return EXIT_SUCCESS;

Please remember that you can learn only if you practice ;)Continuing from my comment, one easy and logical approach is simply to tokenize the words in the first string using strtok (or whatever method you prefer). Allocate storage for each word found and store the words in a temporary char **tmp variable. The tokenize the second string, and compare each word from the first string with each token from the second. If they match, add a pointer to the word in the first array as a pointer in your results array. (you need not allocate additional storage, as all your char **results variable will hold are pointers to the memory already allocated in tmp. (just don't free tmp before you are finished using result)
Since you know how many comparisons resulting in a match, outputting each of the words in result is a simple matter.
To put all the pieces together you could do something like the following:
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

enum { NPT = 10, MAXC = 32 };

int main (int argc, char **argv) {

    char *s1 = argc > 1 ? argv[1] : (char[]) { 
                        "My dog has fleas and my cat has none." },
         *s2 = argc > 2 ? argv[2] : (char[]) { 
                        "My frog likes the dog and the rat like the cat. "},
         *delim = " \t\n.,",
         **result = malloc (NPT * sizeof *result),
         **tmp = malloc (NPT * sizeof *tmp);
    int n = 0, r = 0;

    if (!result || !tmp) { /*... handle mem error ...*/ }

    printf ("finding common words between:\n s1: %s\n s2: %s\n", s1, s2);

    /* tokenize all words in s1, save in tmp */
    for (char *p = strtok (s1, delim); p && n < NPT; p = strtok (NULL, delim))
        tmp[n++] = strdup (p);

    /* tokenize all words in s2, compare against words in tmp, save result */
    for (char *p = strtok (s2, delim); p && r < n; p = strtok (NULL, delim)) {
        for (int i = 0; i < n; i++)
            if (strcmp (p, tmp[i]) == 0)
                result[r++] = tmp[i];
    }

    if (r) printf ("\ncommon words:\n"); else printf ("\nno common words.\n");
    for (int i = 0; i < r; i++)
        printf ("  %s\n", result[i]);

    free (result);      /* free all allocated memory */
    for (int i = 0; i < n; i++)
        free (tmp[i]);
    free (tmp);

    return 0;
}

In principle, the compiler is at leisure to choose how to interpret the file identifier presented in an #include directive (i.e. "sample_B.h"), but in practice, every compiler you're likely ever to meet interprets it as a file name or path.  Thus, if you have a file whose (only) simple name is sample_C.h, and you have no allowable way to provide another name for it (by copying it or creating a symlink to it, for example) then it is unlikely that there is any way that file will ever be chosen to satisfy an #include "sample_B.h" directive.
If, however, the two headers have the same simple name but reside in different directories, e.g. src/sample_B.h and custom/sample_B.h, then it is normally possible to influence which is selected via compiler options that affect the search path for include files. /* Create a new empty stack. */
Stack* Stack_new() {
    Stack* s = malloc(sizeof(Stack));
    s->top = -1;
    s->size = 10;
    s->data = malloc(s->size * sizeof(char*));
    return s;
}

/* Deletes the memory associated with the given stack. */
void Stack_delete( Stack* s ) {
    while ( s->top >= 0 ){
        free( s->data[(s->top)--] );
    }

    free( s->data );
    free( s );
}

/* Pushes a copy of the provided NUL-terminated string unto the stack. */
void Stack_push( Stack* s, const char* str ){
    if (full(s)) {
        s->size += 10;
        s->data = realloc(s->data, s->size * sizeof(char*));
    }

    s->data[++(s->top)] = strdup(str);
}

/* Returns the string that was removed from the stack. */
/* The returned string needs to be freed. */
/* Returns NULL if the stack is empty. */
char* Stack_pop( Stack* s ) {
    if (empty(s)) {
        return NULL;
    }

    return s->data[(s->top)--];
}

/* Returns true if the stack is empty. */
int Stack_empty( const Stack* s ) {
    return s->top == -1;
}

/* Returns true if the stack is full. */
int Stack_full( const Stack* s ) {
    return s->top == s->size - 1;
}
